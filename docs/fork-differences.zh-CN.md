# 本仓库与官方 DBX 的区别

本仓库是基于 [官方 DBX（t8y2/dbx）](https://github.com/t8y2/dbx) 的修改版。以下只介绍本仓库新增的 **Web 单进程多账号模式**；桌面端、CLI 和原有单用户 Web 模式仍沿用官方项目的使用方式。这里的对比以本次改动所基于的官方代码版本 `cb4406c715bc778d101f7ca3c9f8737b53392071` 为准，不能代表官方后续版本的功能状态。

| 项目 | 官方版本（上述基线） | 本仓库新增的多账号模式 |
| --- | --- | --- |
| 登录 | Web 使用原有密码登录机制 | 通过通用 OpenID Connect（OIDC）身份提供方登录；登录页跳转到提供方 |
| 账号标识 | 单个 Web 工作区 | 使用 ID token 中的签发方 `iss` 与用户标识 `sub` 组成唯一账号身份；邮箱、用户名和显示名称不作为隔离依据 |
| 工作区数据 | 一个 Web 数据目录 | 每个账号使用独立的数据目录、SQLite 文件、凭据加密密钥、连接配置、连接池和运行状态 |
| 服务进程 | 常规 `dbx-web` 启动方式 | 一个 OIDC 网关进程加一个共享的 `dbx-web` 后端进程；所有账号由同一个后端进程处理，无需每账号启动容器或进程 |
| 浏览器数据 | 原有浏览器缓存方式 | 检测到登录账号变化时清理该站点的本地缓存和指定 IndexedDB 数据，避免把上一个账号的界面状态带给下一个账号 |
| 功能范围 | 原有 Web 功能 | 为限制服务器本地资源访问，多账号入口禁用部分功能，见下文 |

新增的 OIDC 网关采用授权码流程和 PKCE，校验 ID token 的签名、签发方、受众、有效期与 `nonce`。网关只在验证身份后将账号键交给后端；后端要求网关生成的内部密钥，且只监听 `127.0.0.1`。每个账号的数据目录位于 `DBX_DATA_DIR/tenants/<账号键>`，账号键由 `SHA-256(iss + NUL + sub)` 计算。

## 对使用者的影响

- 使用此模式需要管理员配置 OIDC 身份提供方并从本仓库源码构建前后端，然后按 [OIDC 多账号部署说明](oidc-multitenant.md) 启动网关。直接运行官方发布的二进制或沿用官方单用户启动命令，不会启用本仓库的多账号登录。
- 每个 OIDC 账号分别保存自己的 DBX 连接信息和本地工作区数据。浏览器切换账号时会清理该站点的本地缓存；这不是为每个账号长期保留一份浏览器缓存。
- DBX 账号隔离不改变目标数据库的权限。如果两个用户各自配置了能够访问同一个数据库的凭据，他们仍能看到该数据库中各自凭据允许访问的数据。需要隔离数据库内容时，还须在目标数据库中配置相应权限。
- 旧的单用户 `dbx.db` 不会自动分配给某个 OIDC 账号；管理员需先确定归属，再单独规划迁移。
- 网关的登录会话保存在内存中，重启后用户需要重新登录。后端默认最多保留 32 个已激活账号的状态，目前没有空闲回收；达到上限后新账号的 API 请求会返回 503，可通过 `DBX_MAX_ACTIVE_TENANTS` 调整。

## 多账号模式下的功能限制

这一模式允许内置的远程数据库连接，但拒绝 SQLite、DuckDB、插件或外部驱动、Agent、SSH 隧道，以及使用服务器本地证书路径、初始化脚本等配置的连接。插件、AI、服务器文件导入导出、文档文件、云同步和 MCP 等相关 API 会返回 403。原有单用户 Web 启动方式不受这些新增限制。

各账号虽然拥有独立的 DBX 数据目录和后端状态，仍共享同一个操作系统进程及其文件和网络权限。部署给互不信任的公网用户时，应限制服务账号的宿主机文件权限和网络出口；单进程模式无法提供进程或容器级安全边界。
